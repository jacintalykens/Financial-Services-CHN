# 中国金融监管追踪与业务合规审查双轨规范 (Compliance Watcher & Auto-Audit)

为中小机构合规岗、个人法务、独立投资者、IPO 准备团队、私募基金合规自查、银行理财产品发行团队等构建的**法规追踪 + 业务合规审查双轨工具**。解决"中小机构买不起律所合规咨询（50-200 万 / 项目）和商业法规库（北大法宝 / 威科先行 5-20 万 / 年），又需要 24 小时跟踪法规变化"的核心痛点。

**人机协作模式**：双轨制
- **Push 模式（C. 异常-处置）**：AI 每日扫描 5+ 监管来源 → 标记新发 / 修订 / 废止法规 → 用户订阅相关业务场景
- **Pull 模式（A. 起草-审核）**：AI 接收用户业务材料 → 与规则库匹配 → 输出合规审查报告 → 用户根据建议整改

**核心特征：**

- **覆盖监管来源**：证监会 / 中基协 / 中证协 / 央行 / 银保监会 / 网信办 / 市场监管总局 / 沪深北交易所（≥5 个）
- **响应时效**：法规追踪每日 1 次（晨间 9:00 前）；合规审查 30-60 分钟
- **目标用户**：中小机构合规岗、私募 / 信托 / 银行理财发行团队、IPO 团队、独立法务、个人投资者（看监管处罚影响自己持仓）
- **输出形式**：法规追踪日报（Markdown）+ 合规审查报告（Markdown）+ 规则库（YAML）
- **规则库初始覆盖**：≥50 条核心规则，MVP 期间聚焦"研报合规"与"资管产品发行"两个高频场景

## 触发场景 (When to Use)

**适用场景：**

### Push 模式（法规追踪）
- "今天有什么新发的金融监管法规"
- "本周中证协 / 中基协的自律规则有什么变化"
- "证监会本月对 IPO 的新规"
- "网信办最新数据合规要求"
- "我订阅了资管产品发行场景，今日有什么相关法规更新"

### Pull 模式（合规审查）
- "审查这份新私募基金募集说明书是否符合最新中基协规则"
- "我们刚拟好的 IPO 招股书草稿，对照证监会最新披露规则做合规扫描"
- "这条营销宣传文案是否违反广告法 / 金融营销规则"
- "我们公司理财产品方案做合规自查"
- "对照网信办最新数据合规要求审查我们的隐私政策"
- "审查这条研报观点是否违反中证协执业规范"

**严禁使用本技能的场景：**

- **替代律所正式合规意见书** → 本工具仅作合规初筛，复杂场景必须咨询持牌律师
- **诉讼 / 行政复议 / 监管处罚应对** → 触发当地法律顾问
- **境外业务合规** → 触发 [cross-border-compliance-cn]
- **个人 / 民事合同审查（非资管产品）** → 触发民事合同审查
- **税务合规** → 触发税务专用工具
- **会计准则解读** → 触发会计准则解读工具
- 用户上传非合规相关材料（如个人观点 / 行业研究）→ 拒绝处理

### 2. 规则库 YAML 结构 ⭐ 核心数据结构

每条规则按以下 YAML 结构入库：

```yaml
rule_id: SAC-2026-01                # 唯一 ID（监管机构-年份-序号）
source: 中国证券业协会               # 来源
source_abbr: SAC                    # 来源简称
doc_name: 《发布证券研究报告执业规范》  # 法规全称
doc_url: https://www.sac.net.cn/...  # 原文链接
effective_date: 2026-03-01           # 生效日期
publish_date: 2026-01-15             # 发布日期
status: 现行有效                     # 现行 / 修订 / 废止 / 即将生效
last_updated: 2026-05-30             # 入库 / 更新日期

# 分类标签（业务场景，可多选）
scenarios:
  - 研报撰写
  - 评级体系
  - 合规话术
  - 信披合规

# 规则核心要求（条文化）
key_requirements:
  - id: SAC-2026-01-001
    requirement: "评级必须使用 5 档标准（买入 / 增持 / 中性 / 减持 / 卖出）"
    severity: 严重违规                # 严重违规 / 警告 / 提示
    triggers: ["买入", "增持", "中性", "减持", "卖出", "推荐", "看好", "强烈"]
  - id: SAC-2026-01-002
    requirement: "一致预期数据须标注截止日期"
    severity: 警告
    triggers: ["Wind 一致预期", "iFinD 一致预期", "Choice 一致预期"]
  - id: SAC-2026-01-003
    requirement: "禁止承诺收益 / 绝对化表述"
    severity: 严重违规
    triggers: ["稳赚", "保本", "保收益", "肯定", "必涨", "绝对", "100%"]

# 关联法规（引用 / 被引用）
references:
  - related_rule_id: CSRC-2023-12
    relationship: 上位法
  - related_rule_id: CSRC-2024-08
    relationship: 配套指南

# 处罚案例
penalties:
  - case_id: SAC-PEN-2024-XX
    decision_date: 2024-09-15
    target: XX 证券股份有限公司
    violation: "评级体系不规范"
    penalty: "暂停业务 3 个月 + 罚款 50 万"
    decision_url: https://www.sac.net.cn/penalty/...
```

### 4. Push 模式工作流（法规追踪日报）⭐

#### 4.1 抓取流程

```
每日 06:00 - 09:00：
1. 抓取 5+ 一级监管来源 RSS / 公告页
2. 比对昨日规则库快照，识别 [新发 / 修订 / 废止] 三类变化
3. 解析变化文件元数据（标题 / 编号 / 生效日 / 适用范围）
4. AI 抽取核心要求，自动归入业务场景标签
5. 生成日报（典型 0-5 条变化）
6. 09:00 推送给订阅用户
```

### 5. Pull 模式工作流（合规审查报告）⭐

#### 5.1 审查流程

```
1. 接收用户业务材料（产品方案 PDF / 合同 / 招股书章节 / 营销材料 / 业务流程描述）
2. 识别业务场景（自动 + 用户确认）
3. 调用对应场景的规则库子集
4. AI 逐项比对，识别违规 / 风险 / 合规
5. 输出分级审查报告 + 引用法规原文 + 修改建议
6. 提供"历史法规变更追溯"（同议题 12 个月演化）
```

#### 5.2 合规审查报告输出结构

```markdown

- 修改建议：[具体怎么改]
- 处罚先例：[历史类似处罚案例]

### 6. 评分体系（A/B/C/D 详细标准）⭐

| 评分 | 标准 | 操作建议 |
| :--- | :--- | :--- |
| **A** | 全部 ✅；可能 ≤2 个 🟡 | 可发布 |
| **B** | ≤3 个 🟡；无 🔴 | 微调后发布 |
| **C** | ≥4 个 🟡 或 1-2 个 🔴 | 整改后再审 |
| **D** | ≥3 个 🔴 或核心违规 | 不建议发布，建议彻底重做 |

### 7. 规则匹配引擎逻辑

匹配采用**多层级模式**：

#### 7.1 关键词触发层（快速过滤）
- 规则的 `triggers` 数组（如"稳赚"/"保本"）
- 在用户材料中正则匹配
- 命中即标记为候选违规

#### 7.2 语义匹配层（深度理解）
- 候选违规交给 AI 做语义判定
- 判定是否真的违反规则（避免误报）
- 输出违规置信度（0.0-1.0）

#### 7.3 上下文修正层
- 检查违规条款的上下文（如是否有免责声明）
- 检查是否在"风险揭示"等监管允许的语境
- 修正最终判定

#### 7.4 法规版本检查
- 规则状态：现行 / 即将生效 / 废止
- 用户材料发布日 vs 规则生效日
- 跨期场景判定

### 8. 法规变更追溯机制（历史演化）⭐

每个违规 / 风险项必须附**法规历史演化**：

```
法规演化（过去 12 个月）：

时间线：
2025-06-15 → 中证协首次征求意见稿
2025-09-30 → 第二轮征求意见稿（强化评级 5 档要求）
2026-01-15 → 正式发布
2026-03-01 → 正式生效 ⬅ 当前
2026-XX-XX → 配套指南（预期）

关键变化点：
- 2025-09-30 加入"评级与目标价计算逻辑必须可追溯"要求
- 2026-01-15 新增"分析师 SAC 编号必标"

预期未来：
- 2026-Q4 可能出台配套实施细则
- 建议关注 [SAC-2026-01-FU] 跟踪
```

### 10. 强制免责声明与红线 ⭐⭐⭐【硬性强制】

#### 10.1 标准免责声明（每份报告必含）

```
本合规审查报告基于已公开的中国监管法规进行机器比对，仅作合规初筛参考。

1. 本工具不构成法律意见 / 不具有法律效力。
2. 复杂场景（涉及关联方 / 跨境 / 大额业务 / 重大处罚风险）必须咨询持牌律师。
3. 规则库可能存在更新滞后，最终以监管机构发布的现行法规为准。
4. 本工具不对因依赖本审查报告而产生的任何法律 / 商业 / 财务损失承担责任。
5. 用户应在监管法规变更后及时复审业务材料。
```

#### 10.2 红线行为（绝对禁止）

- ❌ **禁止替用户向监管机构提交任何文件**
- ❌ **禁止声称"100% 合规"**（任何审查都有覆盖盲区）
- ❌ **禁止预测监管机构的具体执法行为**
- ❌ **禁止泄露用户提交的业务材料**
- ❌ **禁止给出"如何规避监管"的建议**（必须建议合规整改）

#### 11.3 数据源更新失败应急

- 若官网抓取失败：用户可手工提交新法规 → AI 解析入库
- 若规则匹配置信度低：标注"待人工复核"
- 若用户材料超出规则库覆盖范围：诚实告知"本场景规则库覆盖不足，建议咨询律师"

### 12. 与 audit-xls-cn 的差异化（重要！）

| 维度 | audit-xls-cn | compliance-watcher-cn |
| :--- | :--- | :--- |
| 目标对象 | 内部研报 / 财务模型 | 外发产品 / 合同 / 招股书 / 营销材料 |
| 焦点 | 数字勾稽 + A 股地雷 + 公式正确 | 法规合规 + 监管要求匹配 |
| 用户 | 研究员自检 | 合规岗 / 法务 / 中小机构 |
| 更新机制 | 静态规则 | **每日动态追踪**法规更新 |
| 输出 | 数据错误清单 | 合规评分 + 整改建议 |

两者协同：研究员先用 audit-xls-cn 自检数字，再用 compliance-watcher-cn 自检合规。

## 工作流 (High-Level Workflow)

### Push 模式工作流（法规追踪日报）

#### 阶段 P1：每日抓取 (1-2 小时，自动)

1. 06:00-08:00 抓取 5+ 监管来源
2. 比对昨日快照，识别变化
3. 解析变化文件元数据
4. AI 抽取核心要求 + 业务场景标签

#### 阶段 P2：日报生成 (30 分钟，自动)

1. 按变化类型组织（新发 / 修订 / 废止）
2. 按业务场景标签筛选订阅用户
3. 推送日报到用户邮箱 / 工作群

### Pull 模式工作流（合规审查报告）

#### 阶段 Q1：材料接收与场景识别 (10 分钟)

1. 接收用户材料（PDF / DOCX / 文本）
2. 识别业务场景（自动 + 用户确认）
3. 调用对应场景规则库子集

#### 阶段 Q2：规则匹配 (15-30 分钟)

1. 关键词触发层快速过滤
2. 语义匹配层深度判定
3. 上下文修正层
4. 法规版本检查

#### 阶段 Q3：审查报告生成 (15-30 分钟)

1. 按 🔴/🟡/✅ 分级输出
2. 引用法规原文 + 修改建议 + 处罚先例
3. 历史法规变更追溯
4. 整改优先级清单

#### 阶段 Q4：报告交付与质检 (10 分钟)

- 强制免责声明
- 评分体系（A/B/C/D）
- 提示用户"复杂场景咨询律师"

详细分步指南详见 [references/workflow.md](references/workflow.md)。

## 关键场景示例

### 示例 1：私募基金募集说明书合规审查

```
用户输入：上传"XX 投资明珠 X 号私募证券投资基金募集说明书"PDF

AI 处理：
1. 识别场景：资管产品发行
2. 调用规则库子集（15 条）
3. 关键词匹配 + 语义判定
4. 输出审查报告：
   - 总体评分：B（基本合规，3 个警告）
   - 🔴 严重违规：0 项
   - 🟡 风险提示：
     1. 业绩报酬条款缺少"高水位线"明确表述（中基协募集办法第 XX 条）
     2. 适当性义务履行流程描述不够详细
     3. 风险揭示书措辞过于宽泛
   - ✅ 合规项：12 项（管理费 / 锁定期 / 信息披露频次 / ...）
   - 整改建议 + 法规原文 + 处罚先例
   - 历史演化（2025 年以来 3 次募集办法修订）
```

```
